# Isolated Gemini Problem-Finder Pipeline v49

## Decision

All newly started video analyses use a new producer at `analyze-video-v49`. It has no runtime import path to the retired analyzer, its writer, its sanitizers, its stage runner, or historical result decoding.

The producer has exactly two model responsibilities:

1. Gemini 3.6 Flash sees the complete retained video and returns only ordered visible problems with evidence attached to each problem, or an explicit `unable` reason.
2. Gemini 3.1 Flash-Lite receives the immutable problem list plus declaration/catalog context and produces the public coaching presentation. It cannot change problem identity or evidence.

## Quality boundaries

The 3.6 prompt contains no named faults, movement/body checklist, phase breakdown, rubric, score, strength, muscle request, rep-count task, or exercise-specific evaluator concept. It asks the model to find at least four distinct problems when four genuine problems are visibly supported, but explicitly requires fewer or zero when that is all the video supports. This is a search-depth target, not a parser `minItems` rule: an unconditional four-item schema would force quota filler. Declaration fields identify context only and cannot be judged as claims about what happened. `unable` is valid only when the recording cannot support reliable visual problem identification.

The writer must return corrections and next-set items in the exact problem-ID order. Its response is structurally validated and otherwise preserved. Technical exercise/anatomy language is allowed. There are no banned-word patterns, imperative whitelists, overlap gates, sentence truncators, or generic coaching replacements. A malformed response fails permanently for that canonical stage input.

Evidence is never regenerated by the writer. `result-mapper.ts` copies each problem's timestamps, visible evidence, and confidence into the public correction and only adds public-schema metadata.

## Runtime state machine

Each primary or shadow request creates an immutable `analysis_v49_runs` row. Each of `problem_finder`, `coaching_writer`, and `commit` has one `analysis_v49_stage_runs` row, unique by `(run_id, stage)`. Canonically sorted JSON is SHA-256 hashed for stage inputs.

Stage behavior:

- A matching succeeded stage returns its stored output without a model call.
- A matching active lease returns busy.
- An expired lease or provider/network failure can be reclaimed.
- A changed hash is corruption.
- `ANALYSIS_CONTRACT_INVALID` is returned as a permanent failed claim and is not re-executed.
- Commit succeeds only if a primary run is still `analysis_sessions.active_v49_run_id`.
- Shadow completion writes only the shadow run.

The retained short MP4 is downloaded once per invocation, encoded inline, and SHA-256 hashed before the leased stage. The stage hash binds the exact video bytes and request configuration. The lease is longer than the model deadline, preventing a second invocation from entering the same paid call.

## Persistence and reading

`analysis_v49_runs` stores declaration snapshot, mode, status/failure, raw 3.6 problem output, raw Flash-Lite writer output, strict public result, call count, and timestamps. `model_call_telemetry.v49_run_id` associates the exact one-plus-one model calls with a run.

Primary results are read directly from the active v49 run by `analysis-status`. They never fall into historical decoding. Historical `analysis_results` rows remain readable only through `_historical/legacy-result-payload.ts`. Coach chat uses the same explicit routing boundary. Playback for v49 uses the full retained-video duration and never consults an old draft.

New v49 tables have RLS enabled, no anon/authenticated table privileges, and service-role access only. Clients read through authenticated Edge Functions.

## Failure contract

An `unable` 3.6 response persists its exact code/message, ends the pipeline before Flash-Lite, and exposes the message to the app as a retry/reupload failure. It creates no result, scores, muscles, or coaching.

Deterministic parser/schema failures fail the run and session without retrying unchanged input. Provider failures leave the leased stage resumable. A stale primary run cannot replace a newer result.

## Historical quarantine and removal

Historical migrations stay in source control for clean reconstruction. Historical results stay readable. The following active runtime remnants are removed:

- `supabase/functions/analyze-video/`
- `_shared/boundary-free-analysis.ts`
- `_shared/coaching-contract.ts`
- `_shared/legacy-result-adapter.ts`
- active shared score calibration

Historical score/result decoding lives only under `supabase/functions/_historical/`. Old stored coaching is displayed without sanitizer rewriting.

## QA

The local suite proves prompt minimality, zero/one/many problem parsing, attached evidence, unable short-circuiting, exact writer IDs/order, strict public-schema parsing, stage hashing/leasing, stale-run fencing, shadow isolation, fresh/reanalysis routing, and absence of legacy imports.

`scripts/compare-v49-analysis.ts` creates selected shadow runs and reports old versus v49 issues, benchmark coverage, unrelated findings, exercise/equipment specificity, exact model-call counts, client-schema parsing, and generic fallback phrases. Benchmark concepts exist only in `scripts/fixtures/v49-quality-benchmark.json` and never enter the producer prompt.

The retained incline-row input is a valid 9.1-second 720x1280 H.264 video and remains unchanged by shadow runs. Earlier structured/unstructured trials across high/medium/low thinking and 12/4/1 FPS did not consistently reproduce the evaluator-only concepts; repeated Gemini App trials also varied.
