## Processor-deletion investigation limits

The queue is live and has stopped retrying the 18 failures. Source `gemini-files.ts` treats 404 as already removed, but preserves 403 as a failure. The worker retries failures until 12 attempts or expiry and then records terminal failure. This is an unresolved provider cleanup outcome; it does **not** prove 18 recordings remain at Google.

Google documents automatic Files API deletion after 48 hours. Old-file expiry or an identity/project change could explain the response, but neither was proven for these encrypted jobs. The local Gemini key's digest does not match the deployed secret digest, so the local key's successful empty file-list response cannot validate production file ownership or deletion. No encrypted job payload or secret value was exposed. [Google Files lifecycle](https://ai.google.dev/gemini-api/docs/files#delete_uploaded_files).

Apple token-secret names are now present, including client/team/key IDs, private key and encryption key. One Apple authorization custody row exists. This supersedes older documentation saying the Apple keys were absent, but presence alone does not prove successful token revocation. [Apple account-deletion guidance](https://developer.apple.com/support/offering-account-deletion-in-your-app/).
